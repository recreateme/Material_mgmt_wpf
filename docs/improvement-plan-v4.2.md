# 原料管理系统改进计划（v4.2）

> 状态：阶段 0～4 已完成（含文档、v4.2.0 打包、生产备份副本迁移演练）  
> 基线版本：WPF v4.1.6  
> 目标版本：WPF v4.2.0  

> 相关文档：[quickstart.md](quickstart.md) · [PROJECT.md](PROJECT.md) · [TECH.md](TECH.md) · [DEPLOY.md](../DEPLOY.md)

## 1. 背景与问题

使用部门反馈三类效率问题：

| # | 反馈摘要 | 现状（v4.1.6） | 痛点 |
|---|----------|----------------|------|
| C | 同一库下不想反复退出登录切换「管理 / 称量」 | 登录门户身份单选；`admin` / `operator` 导航硬隔离；单主窗单会话 | 兼岗实验员改配方与称量来回切账号成本高 |
| A | 列表批量操作不便；希望基于已有配方复制微调 | 材料/配方已有勾选与批量删，遇引用整批中止；**无**复制配方 | 清数据与「小改一版配方」仍费时 |
| B | 配料/称量过程导航与进度不直观；长配方参数页按钮被挤出 | 确认即下一步，**不能**回已确认步；无步骤总览；工艺参数弹窗长内容易裁切底栏 | 易误操作、难纠错、长配方无法点「开始」 |

另约定：生产库将另行提供，本计划先固化迁移规则与验收标准。

## 2. 目标与非目标

### 2.1 目标

1. **角色重划**：固定两种角色——系统管理员 / 业务人员；取消 root；登录不再选手动身份。
2. **双窗协作**：业务人员主窗做主数据与工单历史，称量窗专职称量链路；单 DeviceHub、单称量会话。
3. **批量与复制**：巩固列表批量删除体验；支持「复制配方 → 改名改步骤 → 新配方」。
4. **称量进度与回称**：侧栏展示每步原料；绿/灰区分完成与待做；可点已完成步重称；空格确认进下一步。
5. **弹窗布局**：工艺参数等长内容弹窗底栏固定、内容区可滚。
6. **审计**：人员与关键业务操作写入 `audit.log` 事件补齐（查询 UI 下期）。

### 2.2 非目标（本期不做）

- 自定义角色模板 / 细粒度权限矩阵（仅固定两角色）
- 管理端「审计日志查询界面」
- 材料复制、配方版本族/继承
- 批量删除「部分成功跳过」（仍整批失败）
- 多称量窗、多进行中称量会话
- 重称时自动作废「第 N 步之后」的全部记录（若质检后续要求，另开变更）

## 3. 决策摘要（已确认）

### 3.1 优先级

**角色与双窗 → 批量/复制 → 称量进度与弹窗布局**

### 3.2 角色与权限

| 能力 | 系统管理员 | 业务人员 |
|------|------------|----------|
| 业务人员账号增删 | ✓ | ✗ |
| 重置业务人员密码 | ✓ | ✗ |
| 原材料 CRUD | ✗ | ✓ |
| 配方 CRUD / 复制 / 步骤编辑 | ✗ | ✓ |
| 开始称量 / 称量窗 / 我的工单 | ✗ | ✓ |
| 全部工单历史 | ✗ | ✓ |
| 系统设置（串口等） | ✓ | ✓ |

- 登录：**取消**「操作员 / 管理员」单选；仅用户名 + 密码，按账号角色加载导航。
- **舍弃 root**：迁移时 **直接删除** `root` 用户行；代码移除 Root 特权路径。
- 迁移前必须校验：**至少存在一名系统管理员**，否则中止删 root。

### 3.3 账号迁移映射

| 现账号类型 | 迁后 |
|------------|------|
| `operator`、现场操作员（如 `王瑶`） | 业务人员 |
| `admin` 及原管理员类 | 系统管理员 |
| `root` | **删除** |

生产库文件由现场后续提供；实现时以本表为默认规则，可按实库微调脚本。

### 3.4 双窗

| 项 | 约定 |
|----|------|
| 主窗（业务人员） | 原料、配方、工单历史、设置；**不进**称量页 |
| 主窗（系统管理员） | 账号维护、设置 |
| 称量窗 | 开始称量、称量中、我的工单 |
| 身份 | 同一登录账号 |
| 硬件 | 单例 `DeviceHub`；**仅一个**称量窗 / 称量会话 |
| 扫码 | 空闲：跟前台焦点窗；存在进行中称量：称量窗独占 |
| 生命周期 | 关称量窗 ≠ 登出；主窗退出登录则两窗皆关；进行中工单不因关窗自动取消 |

### 3.5 批量与复制

- 列表继续以复选框批量删除原料、配方等；引用冲突时 **整批失败** 并提示原因。
- **复制配方**：自动生成新 `FML-` 编码；名称默认「原名 - 副本」（可改）；创建成功后进入步骤编辑器微调上下限/增删步骤/调序。

### 3.6 称量进度与回称

- 称量页 **侧栏步骤列表**：每步显示原料名称；绿色=已完成，灰色=待做；当前步高亮。
- 保留现有确认逻辑；合格确认或空格后进入下一待称材料。
- 可点击 **已完成** 步骤重新称重：作废/替换该步有效记录，**其后已完成步骤保留**。
- **禁止**点击尚未轮到的未来步以跳步开称。

### 3.7 弹窗布局

- 工艺参数弹窗：上方可滚动，底栏固定「取消 / 开始」。
- 同期梳理其它长内容弹窗，统一「内容区滚动 + 底栏固定」规范。

### 3.8 审计

在现有 `logs/audit.log` 补齐至少：用户增删、重置密码、登录成功/失败、配方复制、步骤重称（含作废旧记录）、称量窗打开/关闭。管理端查询界面列为下期。

## 4. 分期实施

### 阶段 0 — 基础与迁移准备

- 角色枚举/常量改为 `system_admin` / `business`（或等价中文存储策略，实现时二选一并写迁移）。
- `DbBootstrap` / 一次性迁移：按 §3.3 映射；删 root；禁止无管理员时删 root。
- 登录窗去掉身份 Radio；`NavigationService.CanAccess` 按新权限表重写。
- 种子账号：系统管理员 + 业务人员（不再种子 root）。
- 单测：权限矩阵、迁移规则（可用临时库）。

**退出标准**：旧库备份可迁；新登录仅密码；两角色导航正确。

### 阶段 1 — 双窗与硬件路由

- 称量窗宿主（第二 `Window`），入口仅业务人员可见。
- 主窗导航去掉称量相关页；称量窗注册称量三页。
- `DeviceHub`：焦点路由 + 进行中独占；禁止第二称量窗。
- 退出登录协调关闭子窗；审计开闭窗事件。

**退出标准**：主窗改配方、称量窗称量互不抢串口；独占策略联调通过。

### 阶段 2 — 批量体验与复制配方

- 核对材料/配方（及同类列表）勾选、全选、批量删提示文案。
- 「复制配方」按钮与服务层克隆 `Formula` + `FormulaItems`。
- 审计：复制配方。

**退出标准**：复制后可改步骤并另存为新配方；批量删行为与 §3.5 一致。

### 阶段 3 — 称量进度、回称、弹窗布局

- 称量侧栏进度组件；状态色与点击规则按 §3.6。
- `WorkflowEngine` / `OrderService`：支持定位到已完成步并替换有效 `WeightRecord`。
- `WorkOrderParamsDialog` 底栏固定 + 滚动；长弹窗规范扫尾。
- 审计：步骤重称。

**退出标准**：长配方可点开始；侧栏可回已完成步重称且不可跳未来步。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 删除 root 后无系统管理员 | 迁移事务内先确保 ≥1 名系统管理员，否则中止并提示 |
| 双窗扫码误入主窗筛选 | 进行中独占称量窗；弹窗打开时仍走称量窗；硬件清单加测项 |
| 回称保留后续步不符合质检 | 文档与 UI 明示「仅替换本步」；若现场否决，另开「作废 N 及之后」变更 |
| 称量中主窗改同一配方 | 开工时快照步骤列表；称量窗 `OnShow`/恢复时检测配方变更并提示 |
| 原 admin 升级后不能管配方 | 发布说明 + quickstart 醒目标注；需要管配方的账号改为业务人员 |
| 业务人员可见全员工单 | 已确认接受；若日后要隔离，再加「仅自己的工单」权限 |

## 7. 验收清单（摘要）

### 角色与登录

- [ ] 无身份单选；系统管理员不能进原料/配方/称量
- [ ] 业务人员主窗无称量页，能开称量窗
- [ ] 设置两角色均可进；用户管理仅系统管理员
- [ ] 迁移后 root 不存在；admin→系统管理员；operator→业务人员

### 双窗与硬件

- [ ] 仅一个称量窗；关窗不登出；退出登录关两窗
- [ ] 空闲扫码跟焦点；称量中扫码只进称量窗
- [ ] 进行中工单关窗后可从「我的工单」恢复

### 批量与复制

- [ ] 勾选批量删原料/配方；有引用时整批失败并提示
- [ ] 复制配方得新编码与「- 副本」名，进入编辑后可改步骤并保存

### 称量与弹窗

- [ ] 侧栏步骤名 + 绿/灰/当前高亮
- [ ] 确认/空格进下一步
- [ ] 已完成步可点重称；未来步不可点
- [ ] 长配方工艺参数页底栏按钮始终可点，上方可滚

### 审计

- [ ] 上述关键操作在 `audit.log` 有对应记录
