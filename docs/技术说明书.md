# 原料管理系统技术说明书（v4.4.0）

读者：熟悉称量工艺、电子秤和扫码枪，准备自己改这个程序，或以后做一套类似的单机称量软件。界面操作见 [使用说明书.md](使用说明书.md)。端口参数和排障表的压缩版在 [TECH.md](TECH.md)，文件对照表在 [PROJECT.md](PROJECT.md)，WPF 控件写法在 [wpf-tutorial.md](wpf-tutorial.md)。本说明书把这些串成一条学习路径，不代替那几份速查。

建议顺序：第 1～2 章建立词汇 → 第 4 章知道文件在哪 → 第 5 章跟着三条调用链把程序跑通 → 第 6 章对着现场设备看 → 第 7 章看数据怎么升级 → 第 3 章遇到看不懂的语法再翻 → 第 8 章开始改。

## 1. 这套程序在现场的位置

程序装在称量工位的 Windows 电脑上，读电子秤的克重、读扫码枪的字符串，把结果写入本机 SQLite 文件 `data/material_mgmt.db`。它不驱动阀门、泵或加料机构，也不连接服务器。Excel 导出是事后把有效记录写成文件。

用现场习惯对照四个工程（解决方案 `src/MaterialMgmt.sln`）：

| 工程 | 现场类比 | 里面有什么 | 不能做什么 |
|------|----------|------------|------------|
| `MaterialMgmt.App` | 操作屏 | 窗口、按钮、导航、设备状态栏 | 不写业务规则，不直接 `SaveChanges` |
| `MaterialMgmt.Core` | 联锁与工艺计算 | 状态机、编码、密码规则、筛选与分页计算 | 不引用界面，不打开串口，不访问数据库 |
| `MaterialMgmt.Infrastructure` | I/O 模块 | EF Core、串口、导出、配置文件、各 Service | 不引用 App |
| `MaterialMgmt.Tests` | 不接真机的出厂检验 | xUnit 测试，每个测试自己的临时库 | 不读 `data/material_mgmt.db` |

依赖方向只有一条：App → Infrastructure → Core。Core 放接口（`IConfigService`、`IAuthService`），Infrastructure 提供实现。这样改界面不会改到称重判定，改串口协议也不会改到「超范围不能确认」。

根目录由 `AppPaths` 决定：从 exe 往上找含 `WPF重构计划.md` 的目录。这个文件是哨兵，发布包里也要有，不能删。`config/`、`data/`、`logs/` 都相对这个根目录。

## 2. 程序记住的对象

| 对象 | 类 / 表 | 业务含义 |
|------|---------|----------|
| 原料 | `Material` / `materials` | 编码 `MAT-`、名称。被配方步骤引用时不能删 |
| 配方 | `Formula` / `formulas` | 编码 `FML-`、名称、是否启用。有工单时不能删 |
| 步骤 | `FormulaItem` / `formula_items` | 顺序、原料、克重上下限。`(formula_id, sequence)` 唯一 |
| 工单 | `WorkOrder` / `work_orders` | `in_progress` / `completed` / `cancelled`。工艺参数挂在工单上 |
| 称重记录 | `WeightRecord` / `weight_records` | 一步一条。`IsValid = false` 表示已作废，行仍保留 |
| 账号 | `User` / `users` | 角色 `system_admin` 或 `business`。密码是 bcrypt 哈希 |

一张工单的生命周期：

1. `OrderService.Create` 写入进行中工单（操作员、配方、`WorkOrderParams`）。
2. 每确认一步，`SavePendingWeight` 写入一条有效记录，并抄下当时的上下限、原料编码和名称（快照）、扫码来源。
3. 回称时 `InvalidateValidRecords` 把该步有效记录标成作废，记下人、时间、原因，再重新称。
4. 最后一步确认后 `CompleteWorkOrder`。取消走 `Cancel`。
5. 列表里的删除是软删除（`DeletedAt`），记录还在库里。

三个容易误读的字段：

- **快照**：导出和详情优先用称重当时的上下限与原料名。之后改配方，历史不会跟着变。没有快照的旧记录才回退到当前配方。
- **作废原因**：操作员可选「读数异常 / 放错料 / 加料量需调整 / 其他」。管理员修复重复有效记录时写成「系统修复」。
- **扫码来源** `scan_source`：`serial`、`hid`、`simulated`。旧记录为空。显示文字在 `ScanSources.ToDisplay`。

`formula_erp_bindings` 表还在，界面没有入口，留给以后对接外部单号。

## 3. 读代码需要的语言和技术

每项只讲到能改本仓库的程度。语法细节以对应文件为准，不必先学完一门课。

### 3.1 C# 与 .NET 8

本仓库是 C#、.NET 8。一个 `.cs` 文件通常一个类。看到这些就够往下读：

- `public` / `private`：外部能不能调用。
- 方法参数里的 `?`（如 `string?`）表示可以是空。
- `record`（`WorkOrderParams`、`StepInput`）是只用来传一组值的类型。
- `throw new InvalidOperationException("中文句子")`：服务发现规则不满足。界面 `catch` 后把这句话显示给操作员。编码问题抛 `CodeError`，同样会被对话框接住。
- `async` / `await` 主要出现在启动和数据库迁移。按钮点击大多是同步调用服务。

构建与运行（在仓库根目录）：

```powershell
dotnet build src\MaterialMgmt.sln
dotnet test src\MaterialMgmt.sln
dotnet run --project src\MaterialMgmt.App
```

发布包是自包含的：目标电脑不用另装 .NET。源码调试才需要 .NET 8 SDK。

### 3.2 WPF：画面几乎用 C# 搭出来

WPF 是 Windows 桌面界面框架。标准教材大量使用 XAML 文件描述控件。本项目只有少量 XAML（`App.xaml`、主题），窗口和面板的控件在 C# 里 `new` 出来，见 `MainWindow.xaml.cs`、`Views/Panels/*`。好处是改一个按钮不用在两种文件之间跳；代价是看不到设计器上的拖拽布局。

读界面时抓住三件事：

- **控件树**：`Grid`、`StackPanel` 负责排版，`Button`、`TextBox`、`DataGrid` 负责操作。主题色和按钮外观集中在 `App/Themes`，不要在面板里写死颜色。
- **事件**：`Click += ...` 就是「按下后调用这段代码」。扫码枪的键盘模式走窗口的 `PreviewKeyDown`，由 `HidKeyMapper` 转成字符，再交给 `BarcodeInputService` 拼成一条码。
- **UI 线程**：改按钮文字、刷新表格必须在界面线程。串口回调在后台线程，`BarcodeRouter` 通过 `DeviceHub` 注入的 `Marshal` 切回界面线程再更新画面。可以把它理解成：现场总线的回调不能直接去画操作屏，要投递到操作屏自己的任务里。

弹窗统一继承 `DialogWindow`：Enter 确认，Esc 取消，字段错误写在输入框下。反馈用 `UiFeedback`：`Success` / `Hint` 是右上角提示条，`Info` / `Warn` / `Error` 是对话框，删除确认用 `ConfirmDialog`。业务代码里不要再调用 `MessageBox`，启动失败和未捕获异常除外（那时主题可能还没起来）。

### 3.3 依赖注入：面板不自己 new 数据库

`ServiceCollectionExtensions` 在启动时注册单例：配置、认证、数据库工厂、`OrderService`、`FormulaService`、`MaterialService`、`UserService`、`ExportService`、两个扫码服务。`App.xaml.cs` 再注册导航、`DeviceHub` 和各个面板。

面板构造函数里需要什么服务，就把参数写上。容器负责传入同一个实例。因此给 `OrderService` 加一个依赖后，不用到每个面板里改 `new`。面板是 `AddTransient`，每次进页面可以新建；设备与服务是单例，整个进程共用。

### 3.4 EF Core 与 SQLite

实体类在 `Core/Entities`。`MaterialMgmtDbContext` 把类映射成表。业务代码通过 `IDbContextFactory` 短时间开一个上下文，用完即弃，避免界面长期握着连接。

SQLite 文件即数据库，WAL 模式，拷贝 `material_mgmt.db` 就是备份（同时拷走旁边的 `-wal` 才完整；程序自己的备份由 `DbBootstrap` 做）。不要用数据库工具去改正在被程序打开的那份 `data/material_mgmt.db`。

结构升级不靠手工 `ALTER`。`SchemaMigrations.All` 是有序列表，版本号写入 `PRAGMA user_version`。旧库的版本是 0，从第 1 步按「列不存在才添加」执行到最新。每步一个事务，和版本号一起提交。中途失败则用本次启动前的备份恢复整库。新增字段的步骤写在列表末尾，已发布的步骤不要改。空库按当前模型直接建表，并标成最新版本。`alembic_version` 仍写成 `0006`，给旧的 Python 工具识别。

### 3.5 配置、日志、测试

- `config/settings.ini` 由 `ConfigService` 读写。模板是 `config/settings.example.ini`。`settings.ini` 不进 Git。
- `logs/app.log` 是运行日志（Serilog）。`logs/audit.log` 是业务审计：谁在什么时候确认了哪一步。审计在服务调用成功之后由界面写入，审计失败不影响已经落库的称重。
- 测试用 xUnit。服务测试继承 `TestHost`：每个测试一个临时目录和新库。改规则时先找 `src/MaterialMgmt.Tests` 里同名测试，改断言，再改服务。

### 4.1 从双击到主窗口

`App.OnStartup`：

1. `AppPaths` 定位根目录，初始化日志。
2. 建立依赖注入容器。
3. `DbBootstrap.InitializeAsync`：备份、建库或迁移、空库时写种子账号、角色迁移。
4. 弹出 `LoginWindow`。成功后 `MainWindow.OnLogin`。
5. `DeviceHub.BeginAutoConnectAfterLogin` 按配置连接秤和扫码枪。

`ShutdownMode` 在登录阶段是「显式退出」，避免登录框一关程序就结束。进入主窗口后改为随主窗口关闭。

### 4.2 导航

`AppPage` 枚举是页面身份。`NavigationService.Register` 把枚举绑到面板工厂。`CanAccess` 用 `RolePermissions` 决定谁能进：

- 首页、系统设置：两种角色。
- 用户管理：仅 `system_admin`。
- 原料、配方、工单历史、开始称量、称量中、我的工单：仅 `business`。

主窗口侧栏在 `RebuildNav` 里组装。「开始称量」「我的工单」不是切换主窗口页面，而是 `WeighWorkspace.Open` 打开 `WeighHostWindow`。称量窗口内部再用同一套 `NavigationService` 在「开始称量 / 我的工单」之间切换；称量进行中会进入 `WeighSession` 页，侧栏不一定单独列出这一项。

面板实现 `IPageLifecycle.OnShow` 时，每次显示会刷新数据。实现 `IBarcodeHandler` 的页面能收到扫码。

## 5. 三条调用链

读代码时不要从文件树挨个点开。从下面三条链的入口往下跟，每一步都能在调试器里打断点。

### 5.1 开工单

1. 业务人员打开称量窗口的 `SessionSelectPanel`。
2. 选中配方（点击或扫 `FML-` 码）。`FormulaHasSteps` 为假则不能继续。
3. `WorkOrderParamsDialog` 收集温度、湿度、生产编号等，装进 `WorkOrderParams`。
4. `OrderService.Create(formulaId, operatorId, operatorName, p)` 写入 `work_orders`，状态 `in_progress`，返回新工单 Id。
5. 称量窗口切到 `WeighSessionPanel`，用这个 Id 和配方步骤构造 `WorkflowEngine`。

界面不自己 `new WorkOrder` 再 `SaveChanges`。操作员 Id 来自当前登录用户，避免手填一个不存在的用户导致外键失败。

### 5.2 称一步：扫码、读重、确认

扫码进程序有三条入口，汇合点是 `BarcodeRouter.Publish(code, source)`：

| 来源 | 路径 | `source` |
|------|------|----------|
| USB 串口枪 | `BarcodeSerialService` 按 CR/LF 切出一行 → `DeviceHub.OnSerialBarcode` | `serial` |
| 键盘楔入枪 | 窗口 `PreviewKeyDown` → `HidKeyMapper` → `BarcodeInputService` → `OnHidBarcode` | `hid` |
| 设置页模拟 | 仅管理员按钮 → `SimulateBarcode` | `simulated` |

`BarcodeRouter` 做四件事（单测在 `BarcodeRouterTests`，用真实的 `BarcodeInputService` 当假枪）：

1. 串口路径有效时丢掉 HID 码，避免一把枪被算成两次。
2. `Trim` 后长度小于 4 的丢掉。
3. 记下 `LastCode`、`LastSource`、时间。
4. 经 `Marshal` 到界面线程：先交给 `ResolveBarcodeHandler()` 选出的页面；称量独占时不再广播，否则再触发 `BarcodeRouted`（给弹窗里的编码框填值）。

谁来收，由 `MainWindow` 注入的两个回调决定：

- `IsBarcodeExclusive`：称量进行中为真，扫码只进称量页。
- `ResolveBarcodeHandler`：独占时固定称量页；否则看当前前台是主窗口还是称量窗口，把码交给那一窗的当前页。

称量页 `WeighSessionPanel.OnBarcode`：

- `simulated == true` 直接拒绝。
- 其余交给 `WorkflowEngine.OnBarcode`。和当前步骤原料编码不一致（忽略大小写）则停留在 `WaitingScan` 并报错。一致则进入 `Weighing`，并记住这次的来源，确认时写入 `scan_source`。

读重：`ScaleWorker` 在后台按 Modbus-RTU 轮询，`DeviceHub` 把稳定标志和克重送到称量页，页内调用 `OnWeightUpdate(weight, isStable)`。

状态只有这几个（`WeighState`）：

```
WaitingScan  --扫对-->  Weighing  --稳定且在范围内-->  WeightOk
                  ^         |                              |
                  |         +--稳定但超范围--> OutOfRange --+  （调整后再次稳定）
                  |
                  +--称重中再扫一次，回到 WaitingScan
WeightOk --确认成功--> 下一步的 WaitingScan，或 Complete
```

确认是两段，避免「画面已经跳到下一步，数据库却没写上」：

1. `HasValidRecord`：这一步已经有有效记录则拒绝，防止重复确认。
2. `PrepareConfirm`：状态必须是 `WeightOk`。通过则生成 `PendingWeightRecord`，状态机先不动。
3. `OrderService.SavePendingWeight(...)` 落库，带上快照和扫码来源。
4. 落库成功才 `CommitConfirm`，步骤加一。落库失败则停在当前步，可以再点确认。
5. 若后面的步骤已经有有效记录（回称之后的情况），`SkipWhileCompleted` 跳过它们。
6. 界面写审计日志。审计失败被吃掉，不影响这条称重记录。

读数变旧或断线时，称量页调用 `OnReadingLost`，从 `WeightOk` 退回 `Weighing`，确认按钮再次不可用。

回称：操作员选原因 → `InvalidateValidRecords` → `RewindToStep`。之后已完成的步保留。

### 5.3 事后改说明、导出

工单历史 `AdminHistoryPanel` 打开 `WorkOrderDetailDialog`：

- 读：`OrderService.GetDetail`。工单不存在时抛「工单 {id} 不存在」。
- 写异常说明：`UpdateExceptionNotes`。说明会 `Trim`。成功后界面记审计。

导出 `ExportService`：只写 `IsValid` 的记录；上下限和原料名优先快照；一个工单一个工作表。多选导出时跳过已软删除的工单。测试在 `ExportServiceTests`。

### 5.4 写库约定

App 工程里没有 `SaveChanges`。增删改在四个服务里：

| 服务 | 面板与弹窗 |
|------|------------|
| `MaterialService` | 原料列表、原料弹窗 |
| `FormulaService` | 配方列表、步骤编辑。进行中工单存在时 `EnsureFormulaStepsEditable` 拒绝改步骤 |
| `UserService` | 用户管理。密码先过 `PasswordPolicy.Validate` |
| `OrderService` | 开工、确认称重、完成、取消、删除、详情、异常说明、重复记录修复 |

服务抛出的中文句子就是给操作员看的。新规则加在服务里，并在 `Tests/Services` 补测试，不要加在按钮事件里。

首页、部分历史查询仍是面板内的只读 LINQ。它们不写库。以后如果同一段查询出现两次，再收进服务。

## 6. 设备接入与联调

这一章对应现场接线。参数表和签字清单仍以 [TECH.md](TECH.md) 第一章、[hardware-checklist.md](hardware-checklist.md) 为准，这里说明程序里谁负责哪一段。

### 6.1 两个口不能共用

| 设备 | 类 | 协议 | 配置 |
|------|----|------|------|
| 电子天平 | `ScaleWorker` | Modbus-RTU，默认 9600 8N1 | `[serial]` |
| 扫码枪 | `BarcodeSerialService` | 文本行，CR 或 LF 结尾，长度至少 4 | `[scanner]` |

保存设置时如果两个口相同，程序拒绝。登录后自动连接秤（可关），并按扫码模式打开枪。

`FindScalePort` 向各 COM 发探测帧，把已经指定给扫码枪的口排除在外。第一个给出合法响应的口当作天平。现场协议如果不是现在的读重帧（`01 03 00 00 00 04`）和置零帧（`01 06 00 04 00 01`），改 `ScaleWorker`，不要在界面里拼字节。

排查秤的原始字节：把 `[serial] raw_frame_log` 设为 `true`，`logs/app.log` 会大约每秒多 10 行。查完改回 `false`。

### 6.2 扫码枪的两种接法

推荐 USB 虚拟串口（扫枪说明书上的 USB COM），后缀 CR，9600。程序在 `DataReceived` 里攒字符，遇到回车输出一条。

键盘模式（HID / KBW）把枪当成键盘。`BarcodeInputService` 根据按键间隔把一串击键收成一条码。现场出现过 Shift 粘滞导致条码少字符，所以它只是应急。模式为「自动」且已配置串口时，`BarcodeRouter` 直接丢弃 HID 码。

| `[scanner] mode` | 行为 |
|------------------|------|
| `Auto` | 有端口用串口，没有则 HID |
| 仅串口 | 只开 COM，失败就报错 |
| 仅 HID | 只用键盘楔入 |

设置页的「模拟扫码」只对系统管理员显示，发出 `simulated`。称量页拒绝它，避免联调按钮把工单写脏。原料编码框、搜索框可以拿它填字。

### 6.3 连接与分发分开

`DeviceHub`（App，单例）管：打开和关闭秤、打开扫码串口、定时重连、空闲检测、把秤的读数转给称量页、把三种扫码入口转给 `BarcodeRouter`。

`BarcodeRouter`（Infrastructure）不管串口开关，只处理「这条字符串要不要、交给谁」。因此不启动 WPF 也能测分发。

状态栏 `DeviceStatusBar` 主窗和称量窗各放一个，文字来自同一套状态。异常时变色，点击调用 `DeviceHub` 重连。

### 6.4 联调时看哪里

| 现象 | 先看 |
|------|------|
| 设备管理器里没有 COM | 驱动、线、枪是否仍是键盘模式 |
| 秤已连接但克重不变 | 波特率、协议是否 Modbus、`raw_frame_log` |
| 串口助手能收到、软件没反应 | 助手是否占用了口；软件里端口是否已保存；码长是否小于 4 |
| 扫码进了搜索框而不是称量步 | 称量是否已经开始（未开始则跟随前台窗口）；码是不是 `FML-` 打在了开始称量页 |
| 扫一次进两次 | 串口和 HID 是否同时开着。配好串口后应为串口优先 |
| 确认按钮亮了又灭 | 读数中断，`OnReadingLost` |
| 标签永远「原料错误」 | 标签原文必须等于 `materials.code`。程序不做外部码到 `MAT-` 的对照表 |

改设备相关代码后，至少跑 `BarcodeRouterTests` 和 `WorkflowEngineTests`。真枪仍须在现场用串口模式和 HID 模式各扫一次，自动化环境打不出 HID 扫码枪的硬件时序。

## 7. 数据、账号、发布

### 7.1 迁移现在的三步

| user_version | 内容 |
|--------------|------|
| 1 | 工单工艺参数列、配方 `code`、Alembic 标记 `0006` |
| 2 | 工单软删除；称重快照与作废时间、作废人；给旧记录回填快照 |
| 3 | `void_reason`、`scan_source` |

v3.0、v4.1、v4.2.2 的库副本都能从 0 走到 3，重复启动不会再执行。测试在 `SchemaMigrationTests`。

以后加列：改实体和 `MaterialMgmtDbContext`，在 `SchemaMigrations.All` 末尾加一步 `AddColumnAsync`，不要修改 1～3 步的正文。

### 7.2 账号

`RolePermissions` 只有两角色。旧库里的 `admin` → `system_admin`，`operator` → `business`，`root` 删除。`[migration] legacy_admin_username` 仅在很老的库把某个个人账号并成 `admin` 时填写，密码不变。

密码规则在 `PasswordPolicy`：至少 6 位、不等于用户名、不能等于出厂默认密码。种子账号只在空库创建。默认密码的具体值只出现在本地交付单 `docs/local/初始账号.md`（不进 Git），源码里的 `SeedPasswords` 供程序判断「是不是还在用出厂密码」。文档和提交说明里不要再抄一遍。

连续失败 5 次锁定 60 秒，逻辑在认证服务，界面只显示倒计时。

### 7.3 备份与发布

- 启动前、正常退出、管理员点「立即备份」都会复制数据库到 `data/backup/`，保留 14 份。
- `tools/publish.ps1` 生成 `dist/原料管理系统/` 和 zip。自包含，整夹拷贝。脚本会保留 dist 里已有的数据库和 `settings.ini`。
- 目标机目录需要 `WPF重构计划.md`（哨兵）、`config/settings.ini`、`data/`。详见 [DEPLOY.md](../DEPLOY.md)。

## 8. 自己改，以及做下一套类似系统

### 8.1 不要碰到在用库

界面试验：把编译输出复制到临时目录，排除 `data`、`config`、`logs`，在副本里登录。本仓库开发时用过：

```powershell
robocopy src\MaterialMgmt.App\bin\Debug\net8.0 $env:TEMP\mm_ui_test /E /XD data config logs
```

副本第一次启动会自己建库。自动化测试已经只用临时库，不要再写会打开 `data/material_mgmt.db` 的测试。

### 8.2 三种改动分别动哪些文件

**改一句提示**  
只改对应面板或 `UiFeedback` 的调用。先确认这句话不是服务抛出来的；服务里的句子在 `Tests/Services` 可能被断言过。

**加一个数据库字段**

1. 实体加属性，`MaterialMgmtDbContext` 配好类型和长度。
2. `SchemaMigrations` 末尾追加一步，`AddColumnAsync`，版本号 +1。
3. 读写的那个 Service 方法加上这个字段。面板只传参。
4. 若导出要带上它，改 `ExportService` 和 `ExportServiceTests`。
5. `SchemaMigrationTests` 用旧库副本跑一遍，确认从版本 0 能到新版本，再启动一次不再执行。

**加一条业务规则**

1. 规则放进对应 Service，失败时 `throw new InvalidOperationException("操作员能看懂的句子")`。
2. 在 `Tests/Services` 加一个测试：合法路径成功，非法路径抛这句话。
3. 面板只 `catch` 并显示，不要在点击事件里再判断一遍。需要防连点可以禁用按钮，但判定仍以服务为准（步骤锁定就是保存前再查一次进行中工单）。

### 8.3 下一套类似系统可以留下的骨架

这些不依赖「原料称量」这个行业，换一种「按步骤采集仪表读数并留痕」的工位时可以照搬：

- 四层分法，以及「界面不 `SaveChanges`」。
- `DeviceHub` + 一个与界面无关的 `BarcodeRouter`（或任何「字符串从多个口进来、只交给当前工位」的分发器）。
- 一个纯 Core 的状态机：非法跳转在状态机里拒绝，测试不启动窗口。
- 确认分两段：先生成待写入对象，数据库成功后再让状态机前进。
- 记录上的快照字段：主数据以后会改，历史按当时值导出。
- `user_version` 迁移列表、失败恢复启动备份。
- 提示条、对话框、确认框三分，不在业务代码里直接弹系统消息框。
- `TestHost` 这种「每个测试一个临时目录」的写法。

必须按新工艺重写的部分：状态有哪些、仪表协议帧、表里要记的工艺参数、条码和主数据如何比对、角色各能进哪些页。不要把 `WorkflowEngine` 的五个状态原样套到别的工序上，如果工序不是「扫码 → 等稳定 → 范围内确认」。

### 8.4 建议的练习顺序

1. 按 README 把程序跑起来，用业务人员账号走通 [使用说明书.md](使用说明书.md) 第 4 章。用的是临时副本，不是现场库。
2. 在 `OrderService.Create`、`BarcodeRouter.Publish`、`WorkflowEngine.PrepareConfirm`、`SavePendingWeight` 设断点，做一张两步配方的工单，看第 5 章的链是否和调试器一致。
3. 改一条空状态文案，重新编译，在副本里看到新句子。
4. 给工单加一个可空字段，按 8.2 走完迁移和测试。不要改已发布的迁移步骤。
5. 读 `WorkflowEngineTests`，改一个边界（例如上下限相等是否允许）并让测试先失败再通过。上下限规则目前在 `StepRange` 和步骤弹窗，改之前先看现有断言。
